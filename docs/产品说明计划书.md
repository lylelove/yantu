## 1. 执行摘要

### 1.1 我们在解决什么问题

研究者真正卡住的地方，往往不是「我已经读过的文献之间有什么关系」，而是：

> **我没在看什么？我的盲区长什么样？**

传统文献工具——Zotero 列表、全量引用图谱、推荐算法——都在回答第一个问题。它们把用户已有的文库全部画出来，于是**缺失的东西没有行，也没有节点**，盲区在界面上根本不存在。

**研图 Yantu** 反其道而行：默认隐藏未知，让「看不见」成为界面上一个可见、可操作的状态。用户每读一篇论文、每写一条笔记，地图就向外扩张一圈——**唯一的奖励，是更大的地图**。

### 1.2 产品形态

| 维度 | 说明 |
|------|------|
| **平台** | Tauri 2 跨平台桌面端（Windows / macOS / Linux），支持纯 Web 开发模式 |
| **数据** | 本地优先，支持 Zotero / BibTeX / RIS / CSV / JSON 导入 |
| **联网** | 可选 OpenAlex 扩展，仅发送用户主动请求的单条标识符 |
| **交互** | 暗色 Canvas 地图 + 迷雾机制 + 线索推荐 + 区域版图 + 探索任务 |

### 1.3 为什么适合知乎社区

知乎是中国最大的深度知识问答社区，聚集了大量研究生、科研工作者、跨领域学习者和「认真写长文」的内容创作者。Yantu 的产品哲学——**反信息茧房、以思考换视野、让盲区可被言说**——与知乎「认真你就赢了」的社区气质高度同构。它不是又一个文献管理插件，而是一种**可被讲述、可被展示、可被讨论的研究叙事工具**。

## 2. 核心创作思路

### 2.1 设计原点：从「展示已知」到「揭示未知」

```
传统图谱：  [已读 A] ── [已读 B] ── [已读 C]     →  回答「我知道什么」
研图 Yantu：[已读 A] ··· 迷雾 ··· ? ? ?          →  回答「我还不知道什么」
                      ↓ 点亮
              [已读 A] ── [未读 D] ── ? ?          →  邻接文献浮现
```

这一反转来自一个朴素观察：**列表和全量图谱天生无法表达缺席**。Yantu 把「缺席」做成核心 UI 元素——迷雾不是加载状态，而是**认知边界的可视化**。

### 2.2 核心循环：一个动作，改变地图形状

```
读一篇  →  它点亮  →  照见邻接的陌生文献  →  其中有你没想到的方向  →  读一篇
                ↑                                                      │
                └──────────  写下笔记，照得更远一跳  ←──────────────────┘
```

**刻意去除的元素：**

- 没有分数、等级、连续登录天数
- 没有「完成任务领奖励」的外驱激励
- 没有按相似度排序的推荐信息流

**保留的唯一正反馈：** 地图变大了——因为你真的多知道了一些东西。

### 2.3 三条设计公理

| 公理 | 含义 | 产品体现 |
|------|------|----------|
| **诚实** | 不替用户假装知道 | 导入的文献永远可见；迷雾只用于线上未知文献 |
| **反茧房** | 推荐应拓宽视野，而非加固偏见 | 线索排序刻意压低「和你已读有多像」的权重 |
| **思考有价** | 点击不应等价于理解 | 笔记是唯一的视野增益——写想法，才多照一跳 |

### 2.4 视觉隐喻：光是主角

地图采用暗色背景，因为核心隐喻是**光在黑暗中扩散**：

- **暖琥珀** = 已读（灯光）
- **冷青色** = 已读且写了笔记（灯塔，照得更远）
- **色相** = 你在哪片区域
- **亮度** = 你对它了解多少

两个通道独立编码，互不遮蔽——用户一眼能同时读出「位置」与「认知深度」。

## 3. 产品设计体系

### 3.1 可见度阶梯（迷雾机制）

| 状态 | 含义 | 视觉 |
|------|------|------|
| `fog` | 完全未知 | 不绘制 |
| `sensed` | 知道有东西，不知是什么 | 虚线空心圈 |
| `frontier` | 已识别、可达、未读 | 实线空心圈 + 标题 |
| `lit` | 已读 | 暖色实心 + 光晕 |
| `beacon` | 已读且写了笔记 | 冷色实心 + 呼吸光晕，多照一跳 |

**关键约束：**

- 用户导入的文献至少是 `frontier`——藏起用户自己的文库等于撒谎
- 光只沿强边传播（引用、真实主题重叠），不走弱信号边
- `read → beacon` 必须写笔记——注解是思考过的证据

### 3.2 线索系统：刻意反推荐算法

```
分数 = 0.45 × 陌生度 + 0.30 × 桥梁性 + 0.25 × 可达性
```

普通推荐按「和你已读有多像」排序——那正是研究者需要逃离的信息茧房。Yantu 把**陌生度 + 桥梁性**的权重压过可达性约 3:1。

**最好的线索，是可达但在别处的文献。**

每条线索必须给出人话理由，例如：

- 「『因果推断』你还没有踏入过」
- 「连接『图神经网络』与『可解释性』」

用户通过读「为什么推荐它」来认识自己盲区的形状——这比黑箱推荐更适合被写进知乎长文。

### 3.3 区域版图：让「没去过」可以被说出口

区域用贪心关键词播种（非黑箱聚类），保证：

- **可解释** —— 区域名来自语料，用户能复述
- **稳定** —— 同一份语料永远产出同一批区域
- **可叙事** —— 界面能说出「『强化学习』你从未踏入过」

一片空白的补丁做不到这件事；**一个有名字的空地，才做得到**。

### 3.4 探索任务：由地图推导，不存储进度

探索目标完全由当前 `WorldView` 实时推导，不持久化任何任务进度。因此：

- 无法过期、无法被刷、不需要数据迁移
- 局面变了，任务自己消失
- 唯一奖励仍是：更大的地图

## 4. 整体技术实现方案

### 4.1 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                     React 18 + TypeScript                    │
│  MapCanvas │ LeadsPanel │ RegionsPanel │ Import │ Settings  │
└────────────────────────────┬────────────────────────────────┘
                             │ Zustand Store
┌────────────────────────────▼────────────────────────────────┐
│                      src/state/                              │
│  SaveState 持久化  ←→  buildWorld() 纯函数推导  →  WorldView │
└────────────────────────────┬────────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────────┐
│                      src/game/  （纯逻辑，无 React、无 IO）     │
│  reconcile → edges → regions → fog → leads → quests → world │
└────────────────────────────┬────────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────────┐
│                      src/render/  （Canvas 渲染，无 React）     │
│  layout（可分步力导） │ palette │ draw                         │
└────────────────────────────┬────────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────────┐
│                      Tauri 2 + Rust                            │
│  本地文件系统 │ 窗口管理 │ 未来扩展：后台导入 / 加密备份        │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 核心设计模式：「存的少，推的多」

```
SaveState（持久化）              WorldView（每次推导）
├── papers                       ├── edges       关系
├── progress  已读 + 笔记      →  ├── regions     区域
├── manualEdges                  ├── visibility  迷雾
└── regionNames                  ├── leads       线索
                                 ├── quests      探索任务
                                 └── stats       统计
```

**为什么这样设计：**

| 收益 | 说明 |
|------|------|
| 无同步问题 | 派生状态不可能和存档不一致 |
| 规则可演进 | 改评分/迷雾规则对老存档立即生效，无需迁移 |
| 损坏隔离 | 部分写入只影响某个字段，不会拖垮整个文库 |
| 可测试 | `buildWorld()` 是纯函数，同样输入永远同样输出 |

### 4.3 身份归一（reconcile）

同一篇论文会以不同标识符到达（DOI / OpenAlex id / arXiv id）。若按字面处理，一篇论文会变成互不相连的多个节点，**引用边无法形成，迷雾静默失效**。

`reconcile.ts` 在推导任何边之前做并查集归并，规范 id 从整组标识符中选取（DOI 优先），读进度随合并迁移（`remapProgress`）。

### 4.4 渲染与性能

| 指标 | 实测（1000 篇 / ~19.5k 边） |
|------|----------------------------|
| `buildWorld` | ~95ms（仅在存档变化时） |
| 力导布局收敛 | ~2s（**不可同步**，会卡死 UI） |

**解决方案：**

- **可分步布局** —— `createLayout` + `advanceLayout`，每帧 ~5ms，地图肉眼可见地「落位」
- **结构指纹缓存** —— 布局 `useMemo` 按拓扑指纹而非数组引用做 key，「标记已读」不会触发重布局
- **收敛后自动取景** —— 但若用户已手动移动镜头，不再抢控制权

### 4.5 技术栈明细

| 层级 | 选型 | 理由 |
|------|------|------|
| 桌面壳 | Tauri 2 | 跨平台、体积小、Rust 安全边界 |
| 前端 | React 18 + TypeScript + Vite | 生态成熟、HMR 快 |
| 状态 | Zustand 5 | 轻量、无 boilerplate |
| 地图 | 原生 Canvas 2D | 1000 节点流畅，无 WebGL 依赖 |
| 测试 | Vitest | 纯函数全覆盖 |
| 外部数据 | OpenAlex API | 开放、免费、引用关系完整 |
| 导入 | 自研解析器 | BibTeX / RIS / CSV / CSL-JSON，只读不写原文件 |

### 4.6 代码地图

```
src/
├── game/          纯逻辑，无 React、无 IO
│   ├── reconcile.ts   身份归一（必须先跑）
│   ├── edges.ts       关系推导
│   ├── regions.ts     区域划分
│   ├── fog.ts         迷雾传播 ← 核心机制
│   ├── leads.ts       线索排序 ← 反茧房在这里
│   ├── quests.ts      探索任务
│   └── world.ts       组装 WorldView
├── render/        画法
│   ├── layout.ts      可分步力导布局
│   ├── palette.ts     视觉语言
│   └── draw.ts        Canvas 绘制
├── state/         Store 与 localStorage 持久化
├── services/      OpenAlex 客户端、导入解析、AI 扩展接口
├── components/    UI 面板与交互
└── data/          种子数据与示例存档
```

依赖单向：`components → state → game`。`game` 不知道 React 存在——可独立测试，可替换渲染层。

## 5. 与知乎社区生态的契合度

### 5.1 社区气质同构

| 知乎社区特征 | Yantu 对应设计 |
|-------------|---------------|
| **「认真你就赢了」** | 笔记换视野——思考有回报，点击无回报 |
| **长文深度叙事** | 探索过程天然产生「我是如何走进这个领域的」故事线 |
| **反流量、反标题党** | 无分数等级，无连续签到，无制造焦虑的进度条 |
| **跨领域好奇心** | 线索系统优先推荐「桥梁文献」——连接两个你熟悉但未打通的方向 |
| **专业讨论可引用** | 每条线索带人话理由，可直接改写为知乎回答的论证结构 |

### 5.2 知乎用户画像 × 产品场景映射

| 知乎典型用户 | 在 Yantu 中的行为 | 可产出的知乎内容 |
|-------------|------------------|-----------------|
| **研究生 / 博后** | 导入 Zotero 文库，发现盲区 | 「读博第三年，我才发现自己的文献地图长这样」 |
| **跨考 / 转行学习者** | 从示例地图起步，按线索拓展 | 「零基础入门 XX 领域，我的第一篇论文读什么」 |
| **科研答主** | 写笔记升灯塔，照亮邻域 | 把区域版图截图嵌入知乎专栏，展示知识结构 |
| **文献综述作者** | 用区域面板识别空白_patch | 「写综述前，先用这张地图看清自己漏了哪条脉络」 |
| **科普创作者** | 分享探索任务完成路径 | 「为了写这篇科普，我沿地图走了这样一条路」 |

### 5.3 与知乎内容形态的互补

```
知乎擅长：                    Yantu 擅长：
─────────                    ─────────
文字论证与观点                空间化的知识拓扑
「为什么」                    「还有哪里」
已完成的认知                  进行中的探索
公开讨论                      私密的思考过程（本地优先）
```

**互补关系：** Yantu 是知乎创作者的「探索工作台」——在本地完成地图扩张与笔记沉淀，将有结构、有视觉、有故事线的成果选择性发布到知乎。不是替代知乎，而是**为知乎供给更高信息密度的源头素材**。

### 5.4 社区传播的天然钩子

1. **地图前后对比** —— 「读 10 篇前后，我的学术地图变化」—— 天然适合知乎晒图
2. **盲区自白** —— 「『因果推断』区域一片空白」—— 引发共鸣与讨论
3. **线索理由** —— 每条推荐自带解释，降低「为什么读这篇」的写作成本
4. **反茧房叙事** —— 与知乎上大量「如何打破信息茧房」话题直接对话
5. **本地隐私** —— 研究兴趣不必公开，适合知乎用户对「被算法定义」的警惕

### 5.5 潜在社区集成方向（非 MVP，战略储备）

| 方向 | 价值 |
|------|------|
| **地图快照导出** | 一键生成适合知乎发布的 PNG / 动图 |
| **探索日记模板** | 按「线索 → 阅读 → 笔记 → 新区域」结构导出 Markdown |
| **知乎专栏联动** | 区域名 + 线索理由 → 自动生成专栏大纲 |
| **问答辅助** | 收到「XX 领域怎么入门」→ 用示例地图演示探索路径 |
| **盐选 / 付费专栏** | 深度领域地图 + 阅读路径作为付费内容的知识骨架 |

## 6. 场景价值与典型用户旅程

### 6.1 场景 A：知乎答主写领域入门长文

**痛点：** 「XX 领域怎么入门」类问题知乎上已有大量回答，但多数是线性书单，读者不知道**为什么是这个顺序**。

**Yantu 解法：**

1. 导入该领域 20–50 篇核心论文
2. 标记 3–5 篇已读，观察地图如何点亮
3. 查看「去哪儿」面板的线索理由
4. 沿线索拓展 2–3 个新方向
5. 导出地图截图 + 笔记，形成「我是这样走进来的」叙事

**知乎价值：** 从「书单推荐」升级为「探索路径可视化」—— 读者看到的不是结论，而是**可复现的认知过程**。

### 6.2 场景 B：研究生发现文献盲区

**痛点：** Zotero 里有 800 篇论文，但写开题报告时仍感觉「不知道自己漏了什么」。

**Yantu 解法：**

1. 导入 Zotero 文库（全部可见，无迷雾）
2. 标记真正精读过的一小部分
3. 打开「版图」面板 —— 看到哪些区域从未踏入
4. 点击空白区域，获取跨域线索

**知乎价值：** 「原来我的研究版图长这样」类自省内容，在知乎研究生圈层有稳定受众。

### 6.3 场景 C：跨领域学习者建立全局感

**痛点：** 知乎专栏/回答提供知识点，但缺少**领域之间的拓扑关系**。

**Yantu 解法：**

1. 载入示例地图（五个方向的真实论文数据）
2. 不追求读完，先观察区域之间的连接
3. 选一条「桥梁线索」，读连接两个区域的论文
4. 写笔记，看光如何向第三区域扩散

**知乎价值：** 适合「一张图看懂 XX 与 YY 的关系」类高收藏内容。

### 6.4 场景 D：文献综述前的结构自检

**痛点：** 写综述前不确定自己的阅读是否覆盖了主要脉络。

**Yantu 解法：**

1. 导入综述涉及的所有论文
2. 按真实阅读进度标记
3. 检查区域覆盖度与线索面板中的「高陌生度」节点
4. 针对性补读，地图实时反映结构完整性

**知乎价值：** 可产出「写综述前的自检清单」方法论文章，附带真实地图案例。

## 7. 隐私与信任设计

| 原则 | 实现 |
|------|------|
| **本地优先** | 存档存于本机，可导出纯 JSON 随时带走 |
| **最小联网** | 仅用户点击「联网扩展」时发送单条标识符 |
| **不上传文库** | CSP 限制 `connect-src` 为 `api.openalex.org` |
| **只读导入** | 解析 Zotero/BibTeX 导出文件，不修改原文件 |
| **透明归并** | 导入预览展示识别数、重复数、跳过原因 |

这与知乎用户对「平台掌握我的阅读轨迹」的顾虑形成对比——**Yantu 的探索过程默认私密，公开与否由用户决定**。

## 9. 成功指标

### 9.1 产品指标

| 指标 | 目标 |
|------|------|
| 首次启动 → 看到机制 | ≤ 2 分钟（示例地图） |
| 导入 → 生成第一张个人地图 | ≤ 5 分钟 |
| 1000 篇论文 `buildWorld` | ≤ 200ms |
| 地图交互帧率 | ≥ 30fps（1000 节点） |

### 9.2 社区指标（知乎语境）

| 指标 | 目标 |
|------|------|
| 地图截图 / 探索故事发布 | 用户自发分享，无需官方激励 |
| 「盲区自白」类讨论 | 引发「你的 XX 区域空白吗」互动 |
| 专栏 / 回答引用地图 | 从 Yantu 导出的视觉素材出现在知乎内容中 |
| 入门路径复用 | 社区示例地图被其他用户载入并延伸 |

### 9.3 价值观指标

| 指标 | 检验方式 |
|------|---------|
| 用户感到「视野拓宽」而非「被推荐绑架」 | 线索面板反馈 / 知乎评论 |
| 笔记率 | `beacon / lit` 比值——用户是否真的在思考 |
| 区域覆盖率增长 | 地图「从未踏入」的区域随时间减少 |

## 附录 B：与主流文献工具对比

| 维度 | Zotero / 列表 | 全量引用图谱 | 推荐算法 | **Yantu** |
|------|--------------|-------------|---------|-----------|
| 核心问题 | 我有什么 | 已知之间什么关系 | 下一步读什么 | **我不知道什么** |
| 未知文献 | 不在列表中 | 全部显示 | 按相似度推 | **迷雾隐藏，点亮才现** |

| 数据位置 | 本地 | 本地/云 | 通常需上传行为 | **本地优先** |
| 适合知乎叙事 | 低 | 中 | 低 | **高（探索故事线）** |
