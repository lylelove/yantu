# 研图 Yantu — 游戏化设计说明

> 这份文档说明 Yantu 为什么这样设计。`计划书.md` 记录的是早期"文献可视化工具"方向，
> 本文档描述的探索式设计取代了它。

## 1. 一句话

把你正在研究的领域做成一张**待探索的地图**：你读过的东西会发光，光照到的地方浮现出
邻接文献，没照到的地方留在迷雾里。

## 2. 为什么不是又一个图谱工具

传统文献图谱把"用户已有的文献库"全部画出来，于是它只能回答一个问题：*我已经读过的
东西之间有什么关系*。但研究者真正卡住的地方是另一个问题：**我没在看什么**。

列表和全量图谱天生答不了这个问题——缺失的东西没有行，也没有节点。所以 Yantu 反过来
做：默认隐藏未知，让"看不见"成为界面上一个可见、可操作的状态。

## 3. 核心循环

```
读一篇  →  它点亮  →  照见邻接的陌生文献  →  其中有你没想到的方向  →  读一篇
                ↑                                                      │
                └──────────  写下笔记，照得更远一跳  ←──────────────────┘
```

一次循环只需要一个动作（标记已读），但每次循环都会**改变地图的形状**。这是全部的
游戏性来源：没有分数，没有等级，没有连续登录天数。

## 4. 可见度阶梯

这是迷雾机制的实现核心（`src/game/fog.ts`）。

| 状态 | 含义 | 画法 |
|------|------|------|
| `fog` | 未知 | 完全不画 |
| `sensed` | 隐约可见，知道有东西但不知道是什么 | 虚线空心圈，无标题 |
| `frontier` | 已识别、可达、未读 | 实线空心圈 + 标题 |
| `lit` | 已读 | 暖色实心 + 光晕，照亮邻居 |
| `beacon` | 已读且写了笔记 | 冷色实心 + 呼吸光晕，比 `lit` 多照一跳 |

三条设计约束：

- **自己导入的文献永远至少是 `frontier`。** 用户的文库属于用户，把它藏起来是在对
  用户的已有知识撒谎。迷雾只用于线上拉取的未知文献。
- **光不走弱边。** 同期刊（权重 0.25）这种信号太弱，不足以声称它"揭示"了什么；
  引用和真实的主题重叠才行（阈值见 `PROPAGATION_FLOOR`）。
- **笔记是唯一的"增益"。** `read` → `beacon` 需要写下想法。这不是装饰：注解是你真
  的思考过的证据，而更宽的视野是对思考的回报，不是对点击的回报。

## 5. 线索排序：刻意反推荐系统

`src/game/leads.ts` 的权重是全项目最需要解释的地方：

```
分数 = 0.45 × 陌生度 + 0.30 × 桥梁性 + 0.25 × 可达性
```

普通推荐系统按"和你已读的有多像"排序——那正好是研究者需要逃离的信息茧房。所以这里
把陌生度和桥梁性加起来压过可达性约 3:1：可达性只用来在同样陌生的候选之间打破平局，
以及避免推荐只有一根线连着地图的孤儿节点。

最好的线索是**可达但在别处**的那一篇。

每条线索都必须给出人话理由（"「因果推断」你还没有踏入过"、"连接「图神经网络」与
「可解释性」"）。给不出理由的推荐只是神谕；这里的目的是让用户通过读"为什么推荐它"
来认识自己盲区的形状。

## 6. 区域：让"没去过"可以被说出口

`src/game/regions.ts` 用贪心关键词播种而非黑箱聚类，理由是可解释性和稳定性比聚类
纯度更重要——这些名字是用户思考自己版图的词汇。同一份语料永远产出同一批区域。

区域让界面能说出"「因果推断」你从未踏入过"这种话。一片空白的补丁做不到，一个有名字
的地方才做得到。

## 7. 探索任务不是任务系统

`src/game/quests.ts` 产出的目标**完全由当前地图推导**，不存储任何进度。

因此它们无法过期、无法被刷、也不需要迁移。局面变了它们自己就消失。唯一的"奖励"是
更大的地图——因为确实没有别的东西可拿。

## 8. 架构：存的少，推的多

```
SaveState（持久化）              WorldView（每次推导）
├── papers                       ├── edges       关系
├── progress  已读状态 + 笔记  →  ├── regions     区域
├── manualEdges                  ├── visibility  迷雾
└── regionNames                  ├── leads       线索
                                 ├── quests      任务
                                 └── stats       统计
```

存档只保存**推不出来的东西**。这不是洁癖：

- 派生状态不可能和存档不同步；
- 改评分规则对老存档立即生效，不需要写迁移；
- 部分写入损坏的是某个字段，不是整个文库。

`buildWorld()` 是纯函数，同样的存档永远得到同样的世界（有测试保证）。

## 9. 身份归一：迷雾能不能正常工作的前提

同一篇论文会以不同名字到达：BibTeX 导入知道 DOI，OpenAlex 的引用列表用 OpenAlex id。
如果照面值处理，一篇论文会变成几个互不相连的节点，它们之间的引用边永远不会形成——
于是**你已经读过的论文照不亮它引用的东西**，迷雾静默失效。

所以 `src/game/reconcile.ts` 在推导任何边之前先做并查集归并，并把所有引用重写到规范
id 上。规范 id 从整组的**全部**标识符里选（DOI 优先），而不是只看记录自身的 id——否则
后来一次以该 DOI 为键的导入会改变论文身份，让所有指向它的引用失效。

读进度也要跟着迁移（`remapProgress`），否则合并会让用户已读的论文变回未读。

## 10. 视觉语言

地图是暗色的，因为核心隐喻是光。浅色背景会把话说反：墨水越多代表未知越多，这和我们
要表达的正好相反。

两个通道刻意独立：**色相**表达"在哪片区域"，**亮度**表达"你对它了解多少"。互不遮蔽。

配色纪律：暖琥珀（灯光）= 已读；冷青（灯塔）= 照得更远。除此之外不再增加强调色——
每多一个色相，区域颜色就更难读。

## 11. 性能

计划书要求 1000 节点保持流畅。实测（1000 篇 / 约 19.5k 边）：

- `buildWorld` 约 95ms —— 只在存档变化时跑
- 布局完全收敛约 2s —— **不能同步跑**，否则窗口卡死

所以布局是**可分步**的（`createLayout` + `advanceLayout`）：每帧只用约 5ms 推进物理，
地图肉眼可见地"落位"，全程保持可交互。收敛后自动重新取景，但如果用户已经自己动过
镜头就不再抢——把别人的视野挪走比构图差一点更糟。

另外布局的 `useMemo` 按**结构指纹**而非数组引用做 key：`buildWorld` 每次都返回新数组，
按引用会导致"标记一篇已读"就重跑整个力导模拟。位置只取决于有哪些论文、怎么连接——
读一篇论文改变的是它的颜色，不是它的位置。

## 12. 隐私

- 存档在本地，可导出为纯 JSON（本地优先意味着用户随时能带着数据走）。
- 联网只发生在用户明确点"联网扩展"时，且只发送被扩展的那一个标识符。
- 从不上传文库。CSP 把 `connect-src` 限制到 `api.openalex.org`。
- 导入只读解析，不写原文件。

## 13. 代码地图

```
src/
├── game/          纯逻辑，无 React、无 IO
│   ├── types.ts       领域类型
│   ├── reconcile.ts   身份归一（必须先跑）
│   ├── edges.ts       关系推导
│   ├── regions.ts     区域划分
│   ├── fog.ts         迷雾传播 ← 核心机制
│   ├── leads.ts       线索排序 ← 视野拓宽在这里
│   ├── quests.ts      探索任务
│   └── world.ts       组装成 WorldView
├── render/        画法，无 React
│   ├── layout.ts      可分步的力导布局
│   ├── palette.ts     视觉语言
│   └── draw.ts        canvas 绘制
├── state/         store 与持久化
├── services/      OpenAlex 客户端、导入解析
├── components/    UI
└── data/          种子数据与示例存档
```

依赖是单向的：`components` → `state` → `game`。`game` 不知道 React 存在，也不知道
数据从哪来——所以它可以被完整测试，也可以被换掉渲染层。
